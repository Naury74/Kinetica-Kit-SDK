# ADR-0007: UI와 모션 키트를 중심에 두고 표면 스타일을 고르게 한다

상태: 채택 (2026-10-16)

## 배경

[ADR-0006](0006-host-ui-composer.md) 뒤에 `kinetica-ui` 모듈을 더하면서 다이얼로그, 바텀 시트, 토스트, 차트, 효과 같은 컴포넌트가 200개 넘게 쌓였다.
그런데 README와 문서는 여전히 편집기와 재생기를 SDK의 중심으로 소개했고, 키트는 `GlassButton`, `GlassSheet`, `GlassTheme`처럼 이름부터 글래스 전용이었다.
사용자 의견은 이랬다. "깔끔한 UI나 여러 효과를 제공하고 싶은데, 글래스 UI가 아닌 색상이 적용된 UI를 원할 수도 있다. 쓰는 사람에게 선택권이 필요하다."

## 결정

- SDK 소개와 문서 구성은 UI와 모션 키트를 중심에 둔다. 위젯 보드, 화면 편집기와 재생기, 서버 주도 화면은 함께 제공하는 고급 기능으로 뒤에서 소개한다.
- 글래스는 표면 스타일 가운데 하나가 된다. `SurfaceStyle`은 `Glass(GlassStyle)`, `Solid`(불투명 단색, 테두리, 그림자), `Tonal`(강조색을 옅게 섞은 표면) 셋이고, 프리셋은 `SurfaceStyles`에 둔다.
- 앱 전체는 `KineticaTheme(surface = …)`로, 컴포넌트 하나는 `surface` 파라미터로 고른다. 모든 컴포넌트는 표면을 `Modifier.kSurface` 하나로 그린다.
  단색과 톤 표면은 배경을 기록하지 않으므로 블러 비용이 없다.
- 이름은 중립으로 바꾼다. 테마와 골격은 `KineticaTheme`, `KineticaScaffold`, `KineticaColors`, 컴포넌트는 `K` 접두사, 수정자는 `k` 접두사를 쓴다.
  블러 효과 자체를 가리키는 `Modifier.glass`, `GlassStyle`, `GlassStyles`, `GlassBackdrop`만 글래스라는 이름을 남긴다.
- 버튼, 칩, 카드는 표면과 따로 모양(`KVariant`)과 색 역할(`KTone`)을 고른다.
- 알파 기간이므로 옛 이름의 호환 별칭은 두지 않는다. 대응표는 CHANGELOG에 적는다.

## 결과

- 같은 화면을 글래스, 단색, 톤으로 바꿔 쓸 수 있다. 쇼케이스 첫 화면에서 표면을 고르면 모든 데모가 따라 바뀐다.
- 알파 초기 이름(`Glass*`)을 쓰던 호스트는 코드를 고쳐야 한다.
- 장면 엔진과 편집기의 설계(ADR-0001~0006)는 그대로다. `kinetica-ui`는 다른 Kinetica 모듈에 의존하지 않으므로 UI 키트만 쓰는 앱에는 엔진이 들어가지 않는다.

## 버린 대안

- 글래스 이름을 두고 단색 스타일만 추가하기: `GlassButton`이 단색으로 그려지는 것은 읽는 사람을 헷갈리게 한다.
- 옛 이름을 deprecated 별칭으로 남기기: 알파라 사용자가 적고, 별칭 200여 개가 API를 두 배로 늘린다.
