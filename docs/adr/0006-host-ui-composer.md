# ADR-0006: 호스트 뷰를 자유 배치하는 UI 편집·실행 SDK로 방향을 바꾼다

상태: 채택 (2026-10-13). SDK의 중심은 이후 [ADR-0007](0007-ui-motion-kit-first.md)에서 UI·모션 키트로 옮겼고, 이 문서의 기능은 함께 제공하는 고급 기능으로 남는다.

## 배경

docs 00~26은 도형, 텍스트, 이미지를 그리는 2D 편집기와 모션 엔진을 목표로 했다. 구현해 보니 문서, 명령, 실행 취소, 검증, 좌표, 스냅, 저장을 맡는 엔진은
탄탄했지만, 그 위의 그리기 기능만으로는 호스트 앱이 얻는 것이 적었다. Lottie나 Rive와 경쟁할 만한 제작 도구도 없다.

사용자 검토에서 다른 쓰임새가 나왔다. 실시간 데이터를 보여 주는 호스트 앱의 실제 뷰를 받아 자유롭게 배치하고, 상용 앱 수준의 UI 요소를 Figma처럼
만들어 함께 놓을 수 있는 SDK다. 편집기는 앱 운영자와 디자이너, 일반 사용자가 모두 쓴다.

## 결정

- 같은 저장소와 엔진을 유지하고 다음을 더한다.
  - 노드: `Frame`(배경, 모서리, 테두리, 그림자, 자르기를 갖는 컨테이너), `HostSlot`(호스트가 키로 넘기는 Composable), 텍스트 스타일.
  - 데이터 바인딩: 노드 속성(텍스트, 표시 여부, 이미지, 채우기, 불투명도)을 호스트 데이터 키에 바인딩한다. 코드나 식은 실행하지 않고 키로만 값을 찾는다.
  - 동작: 노드에 동작 이름을 달고, 사용 모드에서 누르면 호스트 콜백에 이름을 넘긴다.
  - 렌더러: Canvas 그리기 대신 노드마다 실제 Compose 요소를 배치한다(`graphicsLayer`로 문서 변환을 그대로 적용).
    그래서 호스트 뷰가 실제로 동작하고, 그룹 불투명도와 자르기는 레이어로 합성된다.
- 편집 모드에서는 편집기가 포인터를 가져가므로 호스트 뷰가 눌리지 않는다. 사용 모드(`KineticaPlayer`)에서는 호스트 뷰와 노드 동작이 그대로 작동한다.
- 모션(키프레임·전환)은 보조 기능으로 유지한다.
- 진행 단계:
  1. 레이어 렌더러, Frame, HostSlot, 바인딩, 동작
  2. Auto Layout, 화면 크기 대응
  3. 컴포넌트, 인스턴스, 디자인 토큰
  4. 서버 주도 재생, 성능, 문서

## 결과

- 문서 형식에 새 노드 종류와 필드가 생긴다. 스키마 버전 1을 확장하므로 이전 문서도 그대로 읽히며, 바뀐 필드는 golden 테스트로 고정한다.
- Canvas 렌더러(`SceneCanvas`)는 PNG 내보내기와 가벼운 미리보기에 남긴다. HostSlot은 Canvas에서 빈 플레이스홀더로 그린다.
- 비교 대상은 DivKit과 Figma다. DivKit은 JSON을 네이티브 UI로 바꾸지만 앱 안 편집기가 없고, Figma는 디자인 도구일 뿐 런타임이 아니다. Kinetica는 앱 안에서 시각적으로 편집할 수 있고, 실제로 동작하는 호스트 뷰를 자유롭게 배치할 수 있다는 점이 다르다.

## 버린 대안

- 글꼴, 필터, 스티커 같은 그리기 기능을 늘려 사진 편집기로 가기: FrameKit과 겹친다.
- 엔진만 공개하기: 수요가 적다.
