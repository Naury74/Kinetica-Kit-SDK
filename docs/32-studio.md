# 32 — 스튜디오 디자인 기능

디자이너와 운영자가 앱 화면과 목업을 만드는 편집기(`KineticaEditor`)의 도형, 텍스트, 내보내기 기능을 정리한다. 화면 렌더러(`SceneLayout`)와
내보내기 렌더러(`drawScene`)가 같은 내부 그리기 코드(ShapeStyle.kt)를 쓰기 때문에 두 결과가 같다.

편집기 색은 `StudioTheme`으로 정한다. 기본은 어두운 테마이고, `StudioTheme.light()`나 시스템 다크 모드를 따르는 `StudioTheme.system()`을 쓸 수도 있다.
편집기 안의 입력란, 칩, 시트는 호스트 앱의 MaterialTheme이 아니라 이 색을 따른다.

여러 노드를 고르면(빈 곳에서 끌어 사각 선택) 함께 감싼 테두리에 핸들이 나온다. 끌면 반대쪽 핸들은 그대로 두고 모두 같은 비율로 크기와 위치가 바뀌며,
회전 핸들은 감싼 테두리 가운데를 축으로 함께 돌린다. 실행 취소 한 번에 되돌아간다.

## 도형

| 도형 | 넣는 곳 | 속성 |
| --- | --- | --- |
| 사각형 | 도구 막대 | 모서리 반지름, 모서리별 반지름 |
| 타원 | 도구 막대 | — |
| 다각형·별 | 도형 더보기 | 꼭짓점 수 3..64, 별 비율(1이면 다각형) |
| 선·화살표 | 도형 더보기 | 선 색, 두께, 점선, 시작·끝 모양(화살표, 원) |
| Frame | 도구 막대 | 모서리별 반지름, 자르기, 자동 배치 |
| 텍스트 | 도구 막대 | 리치 텍스트(아래 참고) |

## 스타일

- 채우기: 없음, 단색, 선형 그라디언트(각도 지정), 원형 그라디언트 중에서 고른다. 텍스트에도 그라디언트를 쓸 수 있다.
- 선: 색과 두께, 점선(`strokeDash`), 열린 경로의 시작·끝 모양(`LineCap`)을 정한다.
- 효과: 바깥 그림자와 안쪽 그림자를 최대 8개까지 넣을 수 있고(X, Y, 블러, 퍼짐, 색), 레이어 블러도 있다. 화면에서는 API 31 이상이면 노드 전체에 블러를 적용하고,
  그보다 낮은 기기와 PNG 내보내기에서는 도형의 채우기와 선에만 적용한다. 텍스트와 이미지는 흐려지지 않는다.
- 그림자가 하나뿐이던 예전 문서(`shadow`)도 그대로 읽는다.

## 리치 텍스트

- 텍스트 전체에는 글꼴(`sans`, `serif`, `monospace`, `cursive`, 호스트 글꼴), 굵기, 기울임, 밑줄과 취소선, 줄 높이, 자간을 정할 수 있다.
- 일부 구간만 바꿀 때는 텍스트 편집 창에서 범위를 선택한 뒤(선택하지 않으면 전체) 굵게, 기울임, 밑줄, 취소선, 크기, 색, 글꼴을 적용한다. 입력란에서도 스타일이 그대로 보이고,
  텍스트를 고치면 구간도 따라 움직인다. 구간 끝에서 이어 쓰면 같은 스타일이 적용된다.
- 호스트 글꼴은 문서에 이름만 저장한다. 앱 최상위에서 `CompositionLocalProvider(LocalSceneFonts provides SceneFonts.of(mapOf("brand" to brandFamily)))`로 넘기고,
  내보낼 때는 `PngExporter(context, fonts = …)`로 넘긴다.
- 데이터 바인딩으로 텍스트가 짧아지면 구간을 새 길이에 맞게 잘라서 그린다.
- 상자 크기는 세 가지다. **고정 크기**는 넘치는 부분을 자르고, **높이 자동**은 너비를 유지한 채 줄 수에 맞춰 높이를 바꾸며, **너비 자동**은 줄을 바꾸지 않고 텍스트 길이에 맞춘다.
  내용에 맞추는 Frame 안에 두면 버튼이나 칩이 텍스트 길이에 따라 늘어난다.

## 내보내기·목업

- `PngExporter`로 PNG를 만든다. `ExportRequest(widthPx = 1080, mockup = MockupFrame(DeviceFrame.Phone))`처럼 목업을 지정하면 배경과 그림자를 깔고
  기기 프레임(휴대폰, 폴더블, 태블릿, 브라우저) 안에 넣어 내보낸다. 기기 프레임은 코드로 그린 단순한 도형이다.

## 컴포넌트·디자인 토큰

- 아무것도 선택하지 않으면 속성 패널에 토큰과 컴포넌트 같은 문서 설정이 나온다.
- **컴포넌트 만들기**는 선택한 Frame을 컴포넌트 원본으로 만든다. 여러 개를 선택했으면 Frame으로 감싼 뒤 만든다. **추가**로 인스턴스를 넣으면 원본의 자식이 복사된다.
- 원본을 고치면 모든 인스턴스에 반영된다. 인스턴스에서 직접 바꾼 텍스트나 색 같은 값은 덮어쓴 값으로 남아, 원본이 바뀌어도 유지된다.
  인스턴스 속성에는 **메인 컴포넌트로 이동**, **오버라이드 재설정**, **인스턴스 분리**(일반 Frame으로 바뀜)가 있다. 인스턴스 크기를 바꾸면 자식은 제약에 따라 움직인다.
- **변형**: 컴포넌트 이름이 `세트/변형` 형태이면(예: `Button / Primary`, `Button / Disabled`) 같은 세트의 변형으로 본다. 원본 속성의 **베리언트 추가**는
  원본을 복사해 오른쪽에 새 변형을 만든다. 세트가 없던 원본은 이때 `이름/Default`가 된다. 인스턴스 속성의 변형 칩으로 변형을 바꾸면
  모양은 새 원본을 따르고, 덮어쓴 텍스트와 색은 레이어 이름 경로가 같은 노드로 옮겨진다.
  세트에 이름이 `Pressed`(또는 `눌림`)인 변형을 만들어 두면, 재생기에서 동작이 있는 인스턴스를 누르고 있는 동안 그 변형으로 보인다. Figma의 인터랙티브 컴포넌트와 같은 방식이다.
  덮어쓴 텍스트나 데이터로 바뀐 텍스트는 그대로 유지되고, 손을 떼면 원래 변형으로 돌아온다.
  인스턴스의 **베리언트 데이터 키**에 키를 적으면 호스트가 `SceneData`의 문자열 값(변형 이름)으로 변형을 고른다(`BoundProperty.Variant`). 코드에서는 `ComponentVariants`를 쓴다.

  ```kotlin
  // 장면의 결제 버튼 인스턴스에 변형 데이터 키 "pay.state"를 바인딩해 둔 경우
  KineticaPlayer(scene, data = SceneData.of("pay.state" to DataValue.Text(if (canPay) "Primary" else "Disabled")))
  ```
- 디자인 토큰은 이름과 색(`#RRGGBB`, `#AARRGGBB`)의 쌍이다. 채우기 아래의 토큰 칩으로 채우기를 토큰에 연결하면 토큰을 바꿀 때 함께 바뀐다.
  색을 직접 고치면 연결이 끊긴다.
- **기본 키트 추가**를 누르면 버튼 세트(Primary, Secondary, Disabled), 칩, 카드, 토글, 입력란, 목록 항목, 탭 바 원본과 `color.brand` 등의 토큰이 artboard 오른쪽 바깥에 들어간다.
  재생기는 artboard 바깥을 그리지 않는다. 코드에서는 `UiKit.starter(...)`를 쓴다.

## 모션 효과

속성 패널의 **모션 효과**에서 누를 때 효과(리플, 축소, 기울이기, 어둡게, 떠오르기, 버스트), 등장 효과(9종, 시간과 지연 지정), 반복 효과(11종, 주기 지정)를 고른다. 효과를 고르면 바로 아래 미리보기에서 움직임을 볼 수 있다. 미리보기를 눌러 누를 때 효과를 시험하고, **다시 재생**으로 등장 효과를 다시 재생한다.
편집 캔버스에서는 효과가 움직이지 않고 **미리보기**와 재생기에서만 보인다. 자세한 내용은 [docs/33](33-effects.md)에 있다.

## 애니메이션

keyframe을 넣을 수 있는 속성은 이동, 배율, 회전, 불투명도, 채우기 색, 선 두께, 너비, 높이, 모서리 반지름, 선 색, 레이어 블러, 첫 번째 그림자의 블러·X·Y·퍼짐·색, 모서리별 반지름(왼쪽 위, 오른쪽 위, 오른쪽 아래, 왼쪽 아래)이다.
모서리별 반지름이 있는 노드에서 전체 모서리 반지름을 애니메이션하면, 왼쪽 위 값과의 차이만큼 네 모서리를 함께 움직여 모양을 유지한다.
timeline 패널의 속성 버튼으로 키를 넣는다. 자동 키를 켜면 속성 패널에서 바꾼 값이 현재 재생 위치에 키로 들어간다. 그라디언트가 있는 노드에서는 그라디언트 시작·끝 색과 각도도 애니메이션할 수 있다.
